# Сканы PDF: Heron-раскладка + VLM (`--scan-layout`)

## Цель

На страницах `full_scan` запускать модель раскладки Heron и использовать её области,
чтобы VLM давала лучший Markdown, а результат Heron можно было посмотреть глазами.

## Ключевой факт

Docling после Heron удаляет области без ячеек текстового слоя. На скане это все текстовые
области, остаются только `picture`. Решение: `keep_empty_clusters=True` в
`LayoutObjectDetectionOptions`. Проверено на скане из `lab1_export.pdf` (150 dpi): стр. 2 —
11 областей (section_header, text, formula, picture, caption, page_footer) вместо 3.

## Поведение

Флаг `--scan-layout` (CLI) / `scan_layout=True` (`parse_document`, `parse_to_markdown`).
Без флага — всё как раньше.

1. `pdf_layout.detect_layout(pdf, numbers)` — отдельный Docling-конвертер (OCR и TableFormer
   выключены, `keep_empty_clusters=True`) только на диапазоне скан-страниц.
   Области: метка, уверенность, рамка в пунктах PDF (начало — левый верх).
2. Отбор областей:
   - `picture`/`chart` → рисунок K; `table` → таблица K (уверенность ≥ 0.5);
   - область ≥ 60 % страницы не вырезается (страница-схема — целиком в VLM);
   - область, на ≥ 80 % лежащая внутри уже взятой, пропускается;
   - нумерация сверху вниз, слева направо;
   - `page_header`/`page_footer` закрашиваются (без метки).
3. Отладка (только с `media_dir`, и без `--vision` тоже):
   `media/debug/scan-NNN-heron.png` (рамки и подписи), `scan-NNN-heron.json`,
   `scan-NNN-masked.png` (что видит VLM).
4. С `--vision`:
   - копия страницы: рисунки и таблицы закрашены белым, в центре метка `[FIGURE K]` / `[TABLE K]`;
   - VLM переписывает текст страницы, метки оставляет на месте;
   - таблица: вырез с рендера ×4 → промпт «таблица в GFM»; нет строк `|` или ошибка →
     ссылка на вырез;
   - рисунок: вырез → `scan-NNN-fig-K.png` → обычный `vision:`-блок (вид `diagram`) + ссылка;
   - метки заменяются результатами; потерянные метки → результат в конце блока страницы.
5. Блок: `<!-- pdf-scan:begin page="N" source="vision" layout="heron" … -->`,
   предупреждение `rendered + heron + vision`.
6. Heron упал → предупреждение `heron layout failed: …`, страница идёт старым путём.

Ответы кэшируются в `.vision-cache`; повторный прогон без запросов к API.

## Тесты

Поддельный `detect_layout` и поддельная VLM (по промпту: страница / таблица / рисунок):
отладочные файлы без vision; слияние по меткам; потерянные метки; крупная область;
отказ Heron; идемпотентность; CLI-флаг. Реальный Heron — тест со skip, если модели нет в кэше.
